Description

Under CR: uses exact time-change method with analytical cumulative hazard. The event times are drawn from the correct inhomogeneous BDI process, giving zero-variance IS weights (logf - logg = constant). Under DD: uses approximate Gillespie with piecewise-constant rates. IS weights have nonzero variance (importance sampling, not exact).

Usage

.bdi_augment_one(
  bt,
  pars8,
  model_bin,
  link,
  tp,
  p_fun = NULL,
  Nhat_fun = NULL,
  Phat_fun = NULL,
  Ehat_fun = NULL,
  max_missing = 10000L,
  rho = 1,
  track_parents = FALSE,
  first_aug_id = 0L,
  step_max = Inf,
  obs_pid = NULL,
  beta_ed = 0,
  attach_fn = NULL,
  deadline = Inf
)

Arguments

bt

Branching times, measured forward from the crown.

pars8

The rate vector in the packed slot layout.

model_bin

Which covariate slots the model uses.

link

Link index: 0 linear, 1 exponential, 2 gaussian.

tp

The present, as a time from the crown.

p_fun, Nhat_fun, Phat_fun, Ehat_fun

The converged mean field, as functions of time; NULL under CR, where the rates are exact.

max_missing

Draw budget for hidden lineages before the draw is abandoned.

rho

Sampling fraction.

track_parents

Whether to record, for every inserted lineage, which lineage it was attached to. The parent is decoded from the same uniform that chose the event, so recording it costs no extra draw and leaves the stream bit-identical to a run without it.

first_aug_id

The id the inserted lineages are numbered from, so that ids stay distinct from the observed ones.

step_max

Cap on the Gillespie step, which is how often the frozen rates are re-evaluated. Inf leaves the step uncapped.

obs_pid

Parent ids of the observed nodes, when the topology is known.

beta_ed

The ED coefficient, which tilts the attachment choice toward the lineages the model gives a higher rate. Zero attaches uniformly.

attach_fn

Exact attachment weights for a D model, or NULL.

deadline

The fit's clock as an absolute proc.time() elapsed value; the draw is abandoned with reason "deadline" once it has passed. Inf (the default) is no deadline.

Details

At rho < 1 a missing lineage still alive at tp is not a rejection but an unsampled extant lineage: the conditioning event is "leaves no sampled descendant", and at the present that is satisfied by being alive and unsampled, an event of probability 1 - rho. Those lineages are returned in $unsampled (birth times) and written with the 5e10 sentinel by .bdi_to_tree_df, so N(t) counts them.

Value

List with $reason: "accepted" (then also $species, $unsampled, $n_alive_at_tp, $logg, and the parent records when track_parents), "max_missing" (more than max_missing missing lineages drawn), "deadline" (the clock ran out during the draw) or "survivor" (a missing lineage still alive at tp; only reachable at rho = 1, where such a tree has f = 0).
